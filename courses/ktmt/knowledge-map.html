01Introduction & Computer OrganizationChapter 00 · Nền tảng kiến trúc máy tính · Mở PDF

1. Organization vs Architecture

  • Computer Architecture: thuộc tính nhìn từ phía lập trình viên — tập lệnh (ISA), kiểu dữ liệu/độ rộng bit, cơ chế I/O, phương pháp định địa chỉ.
  • Computer Organization: cách các thành phần vật lý được triển khai và phối hợp — mạch, tín hiệu điều khiển, chân chip, bus, vi kiến trúc.
  • Microarchitecture: cách hiện thực ISA ở mức tổ chức phần cứng bên trong.

2. Structure & Function

  • Structure: cách các thành phần liên kết với nhau.
  • Function: hoạt động/chức năng của từng thành phần trong cấu trúc.

3. Structural components

  • CPU/Processor: điều khiển hệ thống và xử lý dữ liệu.
  • Main Memory: lưu lệnh và dữ liệu đang dùng.
  • I/O: giao tiếp với môi trường bên ngoài.
  • System Interconnection: đường giao tiếp CPU–Memory–I/O.

4. Functional view

  • Data Processing – xử lý dữ liệu; Data Storage – lưu trữ; Data Movement – di chuyển; Control – điều khiển.

5. Computer abstraction / Multi-level machine

Ứng dụng → ngôn ngữ cấp cao → Compiler → Assembly → Assembler → OS/ISA → Microarchitecture → Digital circuits/Physical devices. Mỗi tầng che giấu chi tiết tầng thấp hơn.

6. Von Neumann / IAS – Stored-program concept

  • Lệnh và dữ liệu cùng nằm trong một bộ nhớ đọc/ghi.
  • Bộ nhớ được truy cập theo địa chỉ, không phụ thuộc kiểu dữ liệu.
  • Thực thi tuần tự, trừ khi lệnh điều khiển luồng làm thay đổi thứ tự.
  • IAS: 1.000 từ nhớ × 40 bit; một từ có thể chứa hai lệnh 20 bit; mỗi lệnh = Opcode 8 bit + Address 12 bit.
IAS registers: PC = địa chỉ cặp lệnh tiếp theo; MAR = địa chỉ ô nhớ; MBR = từ dữ liệu/lệnh trao đổi; IR = opcode; IBR = giữ lệnh phải; AC = accumulator; MQ = multiplier-quotient.
02Computer Evolution & Designing for PerformanceChapter 01 · Lịch sử, cân bằng và đánh giá hiệu năng · Mở PDF

1. Evolution of computer history

  • Generation 1: Vacuum tubes – kích thước lớn, công suất cao; ví dụ ENIAC.
  • Generation 2: Transistors – nhỏ hơn, tin cậy và hiệu quả hơn.
  • Generation 3: Integrated Circuits (IC).
  • Generation 4: Microprocessors/VLSI – CPU tích hợp trên chip; PC và hệ thống hiện đại.
  • Tiếp theo: đa lõi, MICs/GPGPUs, hệ thống nhúng; theo dõi tiến hóa Intel x86, ARM.

2. Moore’s Law & Memory Wall

  • Moore’s Law: mật độ/transistor trên chip tăng theo xu hướng hàm mũ theo thời gian.
  • Memory Wall: tốc độ CPU tăng nhanh hơn khả năng đáp ứng của bộ nhớ; CPU có thể phải chờ dữ liệu.

3. Microprocessor speed techniques

  • Pipelining: chồng lấp các giai đoạn của nhiều lệnh để tăng thông lượng (throughput); không đồng nghĩa một lệnh đơn luôn ngắn hơn.
  • Branch Prediction: dự đoán nhánh sẽ đi theo hướng nào.
  • Speculative Execution: thực thi trước theo dự đoán; nếu sai thì loại bỏ kết quả sai/khôi phục trạng thái phù hợp.
  • Dataflow analysis: phân tích phụ thuộc dữ liệu; lệnh có toán hạng sẵn sàng có thể được thực thi.

4. Performance balance

  • Cân bằng Processor ↔ Memory ↔ I/O ↔ Interconnect; một thành phần chậm có thể thành bottleneck.
  • Giảm nghẽn CPU–Memory: DRAM rộng hơn/bus dữ liệu rộng hơn; dùng cache nhiều cấp và gần CPU; tăng băng thông interconnect.

5. Performance assessment

  • Active/Dynamic power: công suất khi mạch chuyển trạng thái/hoạt động.
  • Static power: công suất rò/leakage khi mạch vẫn được cấp nguồn.
  • Benchmark suite: tập chương trình chuẩn để so sánh hệ thống.
  • Clock rate và CPI phải xem cùng Instruction Count; tăng GHz không tự động bảo đảm chương trình chạy nhanh hơn.
Iron Law: CPU time = Instruction Count × Average CPI × Clock Cycle Time = IC × CPI / Clock Rate.
MIPS: Million Instructions Per Second = IC / (Execution time × 10⁶) = Clock rate / (CPI × 10⁶), khi đơn vị phù hợp. MIPS không luôn là cách so sánh công bằng giữa ISA/chương trình khác nhau.
Amdahl: Speedup = 1 / [(1 − P) + P/S], với P là phần được cải tiến, S là speedup của phần đó. Giới hạn khi S→∞: 1/(1−P).
03Instruction Cycle & InterruptsChapter 02 · Chu kỳ lệnh, Polling và ngắt · Mở PDF

1. Computer function

Thực thi chương trình là lặp lại quá trình lấy lệnh và thực thi lệnh; lệnh được nạp vào Instruction Register (IR).

2. Instruction Cycle

  • Fetch: lấy lệnh từ bộ nhớ vào IR; PC chỉ vị trí lệnh tiếp theo.
  • Decode: giải mã Opcode để biết thao tác.
  • Indirect cycle: chỉ khi cần lấy địa chỉ toán hạng gián tiếp.
  • Execute: thực thi thao tác, có thể lấy toán hạng, tính toán, ghi kết quả hoặc đổi PC.
  • Interrupt check/cycle: kiểm tra và xử lý ngắt nếu đang chờ và được cho phép; sau đó quay lại lệnh tiếp theo.

State labels: IAC (Instruction Address Calculation), IF (Instruction Fetch), IOD (Instruction Operation Decode), OAC (Operand Address Calculation), OF (Operand Fetch), DO (Data Operation), OS (Operand Store), IC (Interrupt Check).

4. Interrupt handling

IRQ → CPU nhận biết (thường sau khi hoàn tất lệnh hiện tại) → Save context (PC/flags và thanh ghi cần thiết) → lấy địa chỉ ISR từ vector → chạy ISR → restore context → return (IRET/RETI tùy kiến trúc).

Interrupt types trong slide: Program/software exception (overflow, divide by zero, illegal instruction); Timer (hardware); I/O (hardware); Hardware failure (hardware).

5. Multiple interrupts

  • Sequential: xử lý ISR lần lượt; ISR hiện tại xong rồi mới nhận ISR tiếp theo theo chính sách.
  • Nested: ISR ưu tiên cao có thể chen vào ISR ưu tiên thấp; phải lưu/khôi phục nhiều lớp trạng thái.
Nhớ: Interrupt không làm mất chương trình chính; CPU lưu trạng thái để quay lại. Polling = CPU hỏi; Interrupt = thiết bị báo.
04Computer Interconnection & Bus ArchitectureChapter 02 · Các module, Bus và liên kết điểm-điểm · Mở PDF

1. Interconnection structures

Computer là mạng các module cơ bản; tập hợp đường kết nối giữa module gọi là Interconnection Structure.

  • Memory module: N từ có cùng độ dài; địa chỉ duy nhất 0…N−1; đọc/ghi từ dữ liệu.
  • I/O module: giao tiếp thiết bị; có thể gửi tín hiệu ngắt đến processor.
  • Processor: đọc lệnh/dữ liệu, xử lý, ghi dữ liệu và phát tín hiệu điều khiển; nhận interrupt.

2. Bus structure & bus types

  • Data Bus: truyền dữ liệu.
  • Address Bus: xác định địa chỉ nguồn/đích; độ rộng liên quan không gian địa chỉ.
  • Control Bus: tín hiệu điều khiển/trạng thái như Read, Write, Interrupt, Clock.
  • Bus hierarchy: nhiều cấp bus giúp đáp ứng chênh lệch tốc độ và loại thiết bị.
  • Bus arbitration: quyết định thiết bị nào được quyền dùng bus khi tranh chấp.
  • Synchronous timing: đồng bộ theo clock; Asynchronous timing: phối hợp bằng handshaking/tín hiệu bắt tay.

3. Bus vs Point-to-Point

  • Shared bus: nhiều thiết bị dùng chung đường truyền; đơn giản nhưng có tranh chấp/bottleneck.
  • Point-to-point: liên kết riêng giữa hai đầu; tăng băng thông và giảm chia sẻ đường truyền.

4. Intel QPI & PCI Express

  • QPI (QuickPath Interconnect): liên kết point-to-point tốc độ cao; có truyền hai chiều; slide minh họa 3.2 GHz, 2 lần truyền/chu kỳ → 6.4 GT/s và 12.8 GB/s mỗi hướng (mức lý thuyết của ví dụ).
  • PCIe: liên kết nối tiếp point-to-point; dùng Lane (các cặp đường truyền); có thể ghép x1, x4, x8, x16 để tăng băng thông. Phân biệt tốc độ mỗi lane và tổng lane.
Điểm thi: nhận diện Data/Address/Control bus; phân biệt synchronous/asynchronous; shared bus/point-to-point; nắm QPI transfer rate theo ví dụ slide.
05Memory Hierarchy & Cache PrinciplesChapter 03 · Tổng quan bộ nhớ, tính cục bộ và Cache · Mở PDF

1. Memory characteristics / design constraints

  • Đặc tính thường xét: vị trí (location), dung lượng (capacity), đơn vị truyền, phương pháp truy cập, hiệu năng (access time/cycle time/transfer rate), công nghệ và tính chất vật lý.
  • Ba ràng buộc: How much? (capacity), How fast? (access time), How expensive? (cost).
  • Fast access → cost/bit cao; capacity lớn → cost/bit thấp và thường access time chậm hơn.

2. Memory hierarchy

Registers → Cache (L1/L2/L3) → Main Memory (DRAM) → Secondary storage (SSD/HDD) → Optical/removable/archive.

  • Đi xuống hierarchy: cost/bit giảm; capacity tăng; access time tăng; tần suất CPU truy cập trực tiếp giảm.

3. Locality of reference

  • Temporal: dữ liệu/lệnh vừa dùng có khả năng được dùng lại sớm.
  • Spatial: địa chỉ gần nhau có xu hướng được truy cập.
  • Sequential: lệnh thường được lấy theo thứ tự liên tiếp.

4. Cache basics

  • Cache nhỏ và nhanh hơn Main Memory; lưu bản sao các block được dùng gần đây/được dự đoán sẽ dùng.
  • Hit: yêu cầu được phục vụ từ Cache. Miss: không có block, cần lấy từ cấp dưới và nạp vào Cache.
  • L1 gần CPU, rất nhanh/nhỏ; L2 lớn hơn; có thể có L3.
Hit ratio = số Cache hits / tổng số yêu cầu. Miss ratio = số Cache misses / tổng số yêu cầu = 1 − Hit ratio.

2. Address fields

  • Offset/Word: chọn byte/word trong block; nếu block có B byte → offset bits = log₂B.
  • Index/Line: chọn line (direct) hoặc set (set-associative).
  • Tag: xác nhận block nào đang nằm tại line/set.
  • Với địa chỉ byte: offset bits = log₂(block size); index bits = log₂(lines hoặc sets); tag = address bits − index − offset.

3. Replacement policy

Khi set/Cache không còn chỗ, chọn block victim để thay. Các ví dụ thường gặp: LRU (ít dùng gần đây nhất), FIFO (vào trước ra trước), Random. Áp dụng theo quy tắc cụ thể mà đề cho.

4. Cache write policy

  • Write-through: ghi đồng thời Cache và Main Memory; đơn giản, nhất quán hơn nhưng tăng traffic ghi.
  • Write-back: chỉ ghi xuống Main Memory khi block bị đẩy ra; giảm traffic, cần theo dõi dirty/modified bit.
Thứ tự giải bài mapping: xác định block size → số lines/sets → tách Offset, Index/Set, Tag → tìm line/set → so Tag để kết luận Hit/Miss → nếu Miss thì chọn victim theo policy.
07Internal Memory & External MemoryChapter 03 · Bán dẫn, đĩa từ, RAID, SSD và Optical · Mở PDF

1. Semiconductor memory

  • Memory cell có hai trạng thái ổn định biểu diễn 0/1; hỗ trợ ghi và đọc.
  • SRAM: lưu bằng flip-flop/logic; không cần refresh khi có nguồn; nhanh, đắt, cell lớn; thường dùng Cache.
  • DRAM: lưu điện tích tụ điện; cần refresh định kỳ; cell nhỏ, rẻ/dung lượng cao hơn; thường dùng Main Memory.
  • Cả SRAM và DRAM đều volatile – mất dữ liệu khi mất điện.

2. ROM family

  • ROM: non-volatile; dữ liệu cố định.
  • PROM: lập trình được một lần.
  • EPROM: xóa bằng tia UV rồi ghi lại.
  • EEPROM: xóa/ghi bằng điện, có thể cập nhật từng nội dung.
  • Flash: một dạng EEPROM, xóa theo khối và nhanh hơn trong cách dùng lưu trữ.

3. Magnetic disk (HDD)

Đĩa platter phủ vật liệu từ; đầu đọc/ghi (head); dữ liệu trên mặt đĩa được tổ chức thành tracks, chia sectors; các track cùng vị trí trên nhiều mặt đĩa tạo thành cylinder.

  • Seek time: thời gian di chuyển đầu đọc đến track.
  • Rotational latency: chờ sector quay đến đầu đọc (trung bình nửa vòng).
  • Transfer time: thời gian truyền dữ liệu.
  • Access time: tổng thời gian định vị + chờ quay + truyền (có thể cộng controller overhead nếu bài cho).

4. RAID / SSD / Optical

  • RAID: ghép nhiều disk thành array để tăng performance và/hoặc reliability/redundancy; phân biệt mục tiêu từng level theo slide.
  • SSD: Flash memory, không có bộ phận chuyển động; access latency thấp, IOPS cao, chống sốc tốt, ít ồn/ít điện hơn HDD; lưu ý write endurance, wear leveling, garbage collection/TRIM.
  • Optical: CD-ROM (đọc), CD-R (ghi một lần), CD-RW (ghi/xóa lại), DVD.
Chip capacity: W × n bits (W words, mỗi word n bits). Ví dụ 1M × 8 = 8 Mbits = 1 MiB (nếu dùng M theo 2²⁰ trong bài tổ chức chip).
08CPU Architecture, Registers & AddressingChapter 04 · CPU, thanh ghi, lệnh máy và phân đoạn · Mở PDF

1. CPU complexity / execution modes

  • Nguyên nhân phức tạp: multiple cores, multiple roles, protection/privilege, hardware priorities, generality, high speed.
  • Execution mode quyết định lệnh nào hợp lệ, vùng nhớ được truy cập, functional units và privilege.
  • Mode change có thể tự động do hardware hoặc chủ động bởi chương trình/hệ điều hành.
  • Privilege & Protection: OS cần quyền cao; ứng dụng chạy với quyền hạn chế.

2. Register organization

  • User-visible: General-purpose, Data, Address (segment pointers/index/stack pointers), Condition codes/flags.
  • Control & Status: PC/IP, IR, MAR, MBR, flags/status register.
  • x86 16-bit: AX, BX, CX, DX; SP, BP, SI, DI; CS, DS, SS, ES; IP; FLAGS.
  • x86 32-bit: EAX, EBX, ECX, EDX, ESP, EBP, ESI, EDI; EIP/EFLAGS; segment registers.
  • x64: RAX, RBX, RCX, RDX, RSP, RBP, RSI, RDI, RIP, RFLAGS; mở rộng general-purpose registers (R8–R15).

3. Important flags

  • CF: Carry – carry/borrow trong phép toán không dấu.
  • PF: Parity; AF: Auxiliary carry; ZF: Zero; SF: Sign; OF: Signed overflow.
  • TF: Trap/single-step; IF: Interrupt enable; DF: Direction for string operations.

4. Machine instruction

Thành phần: Opcode/operation; vị trí lưu operand; số operand tường minh (0/1/2/3); vị trí operand; kiểu và kích thước operand. Operand: address, number, character, logical data.

5. x86 Real Mode segmentation (8086/8088)

  • 20-bit physical address space: 00000h–FFFFFh = 1 MiB; registers segment/offset 16-bit.
  • Logical address: Segment:Offset.
  • Physical Address: PA = Segment × 16 + Offset = (Segment << 4) + Offset.
  • Segment starts at paragraph boundary (địa chỉ chia hết cho 16); segment length tối đa 64 KiB; nhiều cặp Segment:Offset có thể trỏ cùng Physical Address.
  • CS:IP code/next instruction; DS/ES:BX/SI/DI data; SS:SP top of stack; SS:BP stack data/local variables.

6. Addressing modes

Immediate (giá trị nằm trong lệnh); Direct (trường địa chỉ là EA); Indirect (địa chỉ trỏ đến ô nhớ chứa EA); Register; Register Indirect; Displacement/Relative/Indexed; Based-Indexed; Based-Indexed + Displacement; Stack.

Real-mode example: 2A30h:1234h → PA = 2A30h×10h + 1234h = 2B534h. Đừng nhầm Logical address với Physical address.

1. Number systems & binary fraction

  • Positional system: giá trị = tổng digit × radix^vị trí. Decimal base 10; Binary base 2; Octal base 8; Hexadecimal base 16 (A–F = 10–15).
  • Binary ↔ Octal: nhóm 3 bit; Binary ↔ Hex: nhóm 4 bit; số nguyên decimal → Binary bằng chia liên tiếp 2; phần thập phân → Binary bằng nhân liên tiếp 2.
  • MSB: bit trọng số lớn nhất (trái); LSB: bit trọng số nhỏ nhất (phải).
  • Phần lẻ: vị trí sau dấu chấm có trọng số 2⁻¹, 2⁻², 2⁻³…

2. Signed integers

  • Unsigned n-bit: 0…2ⁿ−1.
  • Signed magnitude: 1 sign + magnitude; có +0 và −0.
  • One’s complement: số âm = đảo bit số dương; có hai số 0.
  • Two’s complement: đảo bit + 1; n-bit range = −2ⁿ⁻¹…2ⁿ⁻¹−1.
  • Sign extension: lặp sign bit khi tăng độ rộng signed; Zero extension: thêm 0 bên trái cho unsigned.
  • Byte 8, Word 16, Doubleword 32, Quadword 64 bits.

3. Addition / strings

  • Unsigned overflow → xét CF; signed two’s complement overflow → xét OF. Hai cờ không đồng nghĩa.
  • String: ký tự thường lưu theo ASCII; chuỗi C kết thúc bằng Null (0x00). "19653" = 5 ký tự + null = 6 byte; số 19653 lưu Word = 2 byte.

4. Floating-point / IEEE 754

  • Chuẩn hóa dạng (−1)^S × 1.F × 2^e; exponent lưu = e + Bias; mantissa/fraction bỏ hidden leading 1 với normal numbers.
  • Single 32-bit: 1 Sign + 8 Exponent + 23 Fraction; Bias = 127.
  • Double 64-bit: 1 Sign + 11 Exponent + 52 Fraction; Bias = 1023.
  • Exponent toàn 0: zero/subnormal; exponent toàn 1: infinity/NaN (tùy fraction).

5. Endian / memory layout / GDB

  • Little-endian: LSB byte ở địa chỉ thấp nhất. Big-endian: MSB byte ở địa chỉ thấp nhất.
  • Text: machine code; Data: dữ liệu global/static đã khởi tạo; BSS: global/static zero hoặc chưa khởi tạo tường minh; Heap: cấp phát động; Stack: call frame/local variables.
  • GDB: break đặt breakpoint; run chạy; next chạy dòng kế; step đi vào hàm; continue tiếp tục; print xem giá trị; x/4xb xem 4 byte hex.
Điểm cần nhớ theo slide: Octal là Base 8 (slide ghi Base 7 nhưng chính nó liệt kê chữ số 0–7); ví dụ e7 có nhãn độ rộng trường không khớp phép tính, không dùng nhãn sai làm quy tắc.

1 · CPU Execution Time (Iron Law)

CPU time = IC × CPI × TcycleCPU time = (IC × CPI) / Clock rate

IC = instruction count; CPI = cycles/instruction; Tcycle = 1/frequency.

2 · Average CPI

CPIavg = Σ(ICᵢ × CPIᵢ) / ΣICᵢ

Nếu đề cho tỷ lệ instruction: CPIavg = Σ(fractionᵢ × CPIᵢ).

3 · MIPS

MIPS = IC / (Execution time × 10⁶)MIPS = Clock rate / (CPI × 10⁶)

Đơn vị: triệu lệnh mỗi giây; lưu ý khi so sánh CPU/ISA khác nhau.

4 · Amdahl’s Law

Speedup = 1 / [(1−P) + P/S]Smax = 1 / (1−P)

P = phần chương trình được cải tiến; S = speedup phần đó.

5 · Cache ratios

Hit ratio = Hits / Total requestsMiss ratio = Misses / Total = 1 − Hit ratio

Chú ý phân biệt Cache hit/miss với page hit/miss trong ngữ cảnh khác.

6 · Cache mapping

Direct line = Block no. mod LinesSet = Block no. mod Sets

Offset bits = log₂(block bytes); index bits = log₂(lines/sets); tag = address bits − index − offset.

7 · Disk performance

Access time ≈ Seek + Avg rotational latency + TransferAvg latency = ½ rotation = 30/RPM seconds

Nếu đề cho controller overhead, cộng thêm vào tổng thời gian.

8 · Real Mode address

PA = Segment × 16 + Offset

Ví dụ 2A30h:1234h → 2A300h + 1234h = 2B534h. Địa chỉ vật lý 20-bit trong 8086/8088.

9 · Positional number

N = Σ dᵢ × rⁱ

Binary fraction: bên phải dấu chấm lần lượt ×2⁻¹, ×2⁻², ×2⁻³…

10 · Integer ranges

Unsigned n-bit: 0 … 2ⁿ−1Signed 2’s comp: −2ⁿ⁻¹ … 2ⁿ⁻¹−1

8-bit unsigned: 0–255; signed: −128–127. 16-bit signed: −32768–32767.

11 · IEEE 754

Value = (−1)^S × 1.F × 2^(E−Bias)

Single: Bias 127; Double: Bias 1023. Stored exponent E = e + Bias.

CHAPTER 00 · INTRODUCTION / BUỔI 01

Computer Architecture: thuộc tính hệ thống nhìn từ programmer: ISA, độ rộng/kiểu dữ liệu, I/O mechanism, memory addressing.

Computer Organization: triển khai vật lý để các thành phần phối hợp: mạch, chân chip, tín hiệu điều khiển, bus, peripheral; Microarchitecture là cách hiện thực ISA.

Structure = cách các thành phần liên kết; Function = hoạt động của từng thành phần trong cấu trúc.

4 Functions: Data Processing · Data Storage · Data Movement · Control.

Structural components: CPU/Processor (điều khiển + xử lý), Main Memory (lưu lệnh/dữ liệu), I/O (giao tiếp bên ngoài), System Interconnection (đường trao đổi CPU–Memory–I/O).

Multi-level abstraction: Applications → High-level language → Compiler → Assembly → Assembler → OS/ISA → Microarchitecture → Digital circuits / physical devices. Mỗi mức trừu tượng che giấu chi tiết mức thấp.

Von Neumann / Stored-program: lệnh + dữ liệu ở một bộ nhớ đọc/ghi; nội dung được định địa chỉ theo vị trí; thực thi tuần tự trừ khi lệnh điều khiển luồng thay đổi.

IAS: 1,000 memory words × 40 bit; số có sign + 39-bit value; một word có thể chứa 2 lệnh × 20 bit; mỗi lệnh = 8-bit Opcode + 12-bit Address.

IAS registers: PC = địa chỉ cặp lệnh kế; MAR = địa chỉ memory; MBR = word trao đổi; IR = opcode; IBR = giữ lệnh phải; AC = accumulator; MQ = multiplier-quotient.

Nhớ: Architecture = “máy cung cấp gì cho programmer”; Organization = “phần cứng hiện thực như thế nào”.

IAS fetch trace: MAR←PC; MBR←M[MAR]; lệnh trái (20 bit) tách thành IR←Opcode, MAR←Address; lệnh phải đưa vào IBR; PC chuyển sang word tiếp theo. Khi lệnh trái xong, IBR chuyển sang IR/MAR để xử lý lệnh phải.

IAS word: 40 bit = left instruction 20 bit + right instruction 20 bit. Mỗi instruction = Opcode 8 bit + Address 12 bit. PC trỏ tới instruction pair/word kế tiếp, IBR giữ instruction phải.

IAS arithmetic: LOAD M(X) → AC←M[X]; ADD M(X) → AC←AC+M[X]; SUB M(X) → AC←AC−M[X]. MQ tham gia phép nhân/chia trong mô hình IAS. Theo dõi cập nhật AC/PC/IBR theo đúng vị trí instruction.

CHAPTER 01 · COMPUTER EVOLUTION / HISTORY

Generations: 1st Vacuum tubes (ENIAC); 2nd Transistors; 3rd Integrated Circuits (IC); 4th Microprocessor/VLSI; hiện đại: multicore, MIC, GPU/GPGPU, Embedded systems.

ENIAC: slide gọi là first general-purpose electronic digital computer; lập trình thủ công bằng switches/cables. IAS: stored-program prototype, thiết kế bắt đầu 1946, hoàn thành 1952 (slide).

Intel milestones: 4004 (1971, CPU components trên một chip); 8008 (1972, 8-bit); 8080 (1974, 8-bit general-purpose); 8086 (16-bit, sự xuất hiện x86); 80286 (mở rộng vùng địa chỉ); 80386 (Intel 32-bit); 80486 (cache/pipeline/math coprocessor); Pentium (superscalar); Pentium Pro (register renaming, prediction, dataflow, speculative); Core (dual-core); Core 2 (64-bit theo slide).

ARM: RISC-based, die size nhỏ và yêu cầu điện năng thấp; hay dùng ở embedded, application platforms, secure applications. x86: slide mô tả theo hướng CISC. CISC/RISC: phân biệt theo triết lý ISA, không suy ra hiệu năng chỉ từ tên.

CHAPTER 01 · MOORE / MEMORY WALL / SPEED

Moore’s Law: mật độ transistor trên cùng diện tích chip tăng gấp đôi khoảng 18–24 tháng (cách nêu trong slide). Hệ quả: tăng mức tích hợp, khả năng xử lý/nhớ, giảm kích thước liên kết.

Memory Wall: tốc độ CPU/instructions per second tăng nhanh hơn hiệu năng/độ trễ bộ nhớ; CPU thường phải chờ dữ liệu. Slide minh họa instructions/sec và capacity tăng nhanh hơn memory performance.

Pipelining: chồng lấp các stage của nhiều instruction → tăng throughput; không có nghĩa mỗi instruction riêng lẻ hoàn tất nhanh hơn bằng số stage.

Branch Prediction: dự đoán hướng branch/nhóm lệnh tiếp theo.

Speculative Execution: dùng prediction + dataflow để thực thi trước; kết quả có thể giữ tạm, chỉ dùng khi đường dự đoán hợp lệ.

Dataflow Analysis: xác định phụ thuộc dữ liệu và lệnh có toán hạng sẵn sàng để lập lịch.

Multicore: nhiều core trên một chip; tăng performance tiềm năng mà không chỉ tăng clock; phần mềm phải khai thác song song. MIC = Many Integrated Cores; GPU/GPGPU xử lý song song dữ liệu.

CHAPTER 01 · PERFORMANCE BALANCE / POWER

Balance: Processor ↔ Memory ↔ I/O ↔ Interconnect. Nút nghẽn (bottleneck) ở một thành phần làm giảm hiệu năng toàn hệ thống.

CPU–Memory: DRAM wider / data bus rộng hơn; giảm số lần truy cập bằng cache nhiều cấp, cache gần/trên CPU; tăng interconnect bandwidth bằng bus nhanh hơn.

Processor: thu nhỏ logic gate rút ngắn propagation delay; tăng clock rate; tăng cache size/speed; cải tiến tổ chức/architecture và parallelism. Nhưng clock cao tăng nhiệt/điện và không tự đảm bảo chạy nhanh hơn.

Active/Dynamic power: công suất khi mạch chuyển trạng thái; slide dùng xấp xỉ P ∝ C·V²·f·activity. Static power: leakage khi chip vẫn được cấp nguồn. Giảm V có ảnh hưởng bình phương trong mô hình dynamic power.

Benchmark suite: tập chương trình đại diện workload; đánh giá theo thời gian chạy/score (SPEC trong slide). So sánh cùng workload, cùng điều kiện.

Performance balance checklist: CPU chờ dữ liệu → cải thiện Memory/Cache/bandwidth; I/O quá chậm → cải thiện thiết bị và I/O path; bus tranh chấp → bus hierarchy/point-to-point; CPU-bound → giảm instruction count/CPI/cycle time hoặc khai thác parallelism.

Latency vs throughput: latency = thời gian hoàn tất một tác vụ; throughput = số tác vụ hoàn tất trong một đơn vị thời gian. Pipelining chủ yếu tăng throughput, không đồng nghĩa mỗi instruction riêng lẻ hoàn tất nhanh hơn theo số stage.

CHAPTER 01 · PERFORMANCE ASSESSMENT / FORMULAS

Clock rate (f): cycles/second; Clock cycle time: Tcycle = 1/f. CPI: clock cycles per instruction. Nhiều instruction có CPI khác nhau.

Average CPI: Σ(ICᵢ×CPIᵢ)/ΣICᵢ = Σ(fractionᵢ×CPIᵢ).

IRON LAW: CPU time = IC × CPI × Tcycle = (IC × CPI) / Clock rate.

MIPS: Millions of Instructions Per Second = IC/(CPU time×10⁶) = Clock rate/(CPI×10⁶), khi đơn vị phù hợp. MIPS có thể gây hiểu lầm khi khác ISA/instruction mix.

MFLOPS: Millions of Floating-Point Operations Per Second; chỉ tập trung tốc độ phép toán floating-point.

AMDAHL: Speedup = 1 / [(1−P) + P/S]. P = phần thời gian được cải tiến; S = speedup của phần đó. Nếu phần cải tiến nhanh vô hạn: Smax = 1/(1−P).

So sánh CPU: so tổng CPU time = IC×average CPI×cycle time; không so riêng GHz hoặc CPI. Nếu instruction mix khác nhau, tính CPI trung bình theo tỷ lệ.

Ví dụ nhanh: IC=3×10⁹, CPI=2, f=3GHz → time = 2s. P=.8, S=4 → speedup=2.5. f=2GHz, CPI=1.5 → MIPS≈1333.33.

Power example: khi chỉ đổi điện áp/tần số, với C và activity không đổi, Pdynamic tỷ lệ V²f. V tăng 10% không chỉ làm power tăng 10% mà theo V².

CHAPTER 02 · INSTRUCTION CYCLE / INTERRUPTS

Instruction Cycle: Fetch → Decode → Indirect (nếu địa chỉ gián tiếp) → Execute → Interrupt check/cycle (nếu có ngắt được phép) → fetch tiếp.

Fetch: PC xác định lệnh kế; MAR nhận địa chỉ; memory word chuyển qua MBR; lệnh vào IR; PC cập nhật tùy mô hình. Decode đọc Opcode. Execute có thể lấy operand, tính toán, ghi kết quả hoặc đổi PC.

IAS states: IAC (Instruction Address Calculation), IF (Instruction Fetch), IOD (Instruction Operation Decode), OAC (Operand Address Calculation), OF (Operand Fetch), DO (Data Operation), OS (Operand Store), IC (Interrupt Check).

Polling: CPU liên tục/định kỳ đọc status/command-ready bit. Dễ triển khai nhưng tốn chu kỳ CPU khi không có sự kiện.

Interrupt: device/controller báo CPU qua IRQ khi cần service. Thường được nhận tại ranh giới lệnh; CPU lưu context, chuyển đến ISR, phục vụ rồi khôi phục chương trình.

Handling: IRQ → recognize → save PC/flags/register state cần thiết → locate ISR via vector → execute ISR → restore context → return (IRET/RETI tùy kiến trúc).

Types (slide): Program exception (overflow/divide by zero/illegal instruction); Timer; I/O; Hardware failure. Sequential: ISR tuần tự. Nested: ngắt ưu tiên cao chen vào ISR thấp.

Interrupt transfer: hoàn tất instruction hiện tại → recognize IRQ → save return PC/context → lấy ISR address/vector → chạy ISR → restore context → return/IRET → tiếp tục chương trình ở điểm đã lưu. Interrupt không xóa chương trình chính.

So sánh nhanh: Polling = CPU hỏi thiết bị qua status/command-ready bit theo vòng/chu kỳ; Interrupt = thiết bị báo CPU qua IRQ. Polling đơn giản nhưng có thể lãng phí CPU; interrupt bất đồng bộ và cần context saving/priority.

Multiple interrupts: Sequential = phục vụ lần lượt; Nested = ISR ưu tiên cao có thể tạm dừng ISR ưu tiên thấp. Masking tạm chặn một số interrupt; priority quyết định thứ tự phục vụ.

CHAPTER 02 · INTERCONNECTION / BUS / QPI / PCIe

Memory module: N words cùng độ dài; địa chỉ 0…N−1; read/write. I/O module: quản lý thiết bị ngoài, có thể phát interrupt; có thể trao đổi với memory bằng DMA. Processor: fetch/interpret/process instruction, đọc dữ liệu, ghi kết quả, phát control và nhận interrupt.

Interconnection structure: tập đường kết nối modules. Bus: communication pathway nối ≥2 thiết bị; shared transmission medium; mỗi lần chỉ một transmitter thành công → cần arbitration.

Data Bus: mang dữ liệu; width ảnh hưởng dữ liệu truyền song song. Address Bus: địa chỉ; width quyết định tối đa không gian địa chỉ. Control Bus: memory/I-O read-write, bus request/grant, interrupt request/ACK, clock, reset.

Bus hierarchy: nhiều bus/cấp giảm tranh chấp giữa thiết bị tốc độ khác nhau. Nhiều thiết bị cùng bus → bottleneck.

Arbitration: centralized = arbiter/controller trung tâm; distributed = module tự phối hợp. Master khởi tạo truyền; Slave tham gia trao đổi.

Timing: synchronous dùng clock; asynchronous dùng handshaking. Shared bus có arbitration và contention; point-to-point kết nối riêng, latency thấp hơn, data rate cao hơn và scalability tốt hơn theo slide.

QPI: 4 layers: Physical (phit 20-bit; differential lanes), Link (flow/error control; flit 80-bit gồm 64 data + header/error), Routing (định tuyến packet), Protocol (packet). Ví dụ 3.2GHz × 2 = 6.4GT/s; 16bit/transfer → 12.8GB/s mỗi hướng (lý thuyết theo slide).

PCIe: point-to-point, serial lanes; x1/x4/x8/x16. Tổng băng thông phụ thuộc version × số lane; đừng nhầm PCI legacy shared bus với PCIe.

Bus transfer: master/requester yêu cầu bus → arbiter cấp quyền → master phát address + control → slave nhận diện → data transfer (read/write) → kết thúc/release bus. Bus width và transfer rate quyết định bandwidth.

Bus bottleneck: shared bus có nhiều requester tranh cùng đường truyền; tăng bus hierarchy, phân tách data/I/O path hoặc point-to-point có thể tăng bandwidth và giảm contention.

QPI nhớ 4 lớp: Physical = tín hiệu/lane/phit; Link = flit, flow/error control; Routing = route packet qua link; Protocol = packet/message mức cao. 3.2GHz × 2 = 6.4GT/s; 16bit = 2 byte → 12.8GB/s mỗi hướng.

CHAPTER 03 · MEMORY OVERVIEW / HIERARCHY / CACHE

Memory constraints: Capacity, Access time, Cost. Fast access → cost/bit cao; capacity lớn → cost/bit thấp và access time thường cao hơn.

Hierarchy (nhanh → chậm): Registers → L1 → L2 → L3 → Main Memory/DRAM → SSD/HDD → Optical/Archive. Đi xuống: cost/bit giảm, capacity tăng, access time tăng, frequency CPU access giảm.

Locality: Temporal = vừa dùng có thể dùng lại; Spatial = địa chỉ gần nhau có thể dùng; Sequential = lệnh truy cập liên tiếp. Cache khai thác locality.

Cache: nhỏ/nhanh/đắt hơn main memory; lưu copy các block thường dùng. Hit: request có trong cache; Miss: không có, phải lấy từ cấp dưới và thay line/block phù hợp. L1 nhỏ/nhanh; L2 lớn hơn; có thể có L3.

Hit ratio = Hits / Total requests
Miss ratio = Misses / Total requests = 1 − Hit ratio
AMAT (bổ trợ) = Hit time + Miss rate × Miss penalty.

Memory characteristics: location (internal/external); capacity (word size × number of words); unit of transfer; access method (sequential/direct/random/associative); performance (access time, cycle time, transfer rate); physical type; physical characteristics; organization.

Hierarchy: Registers → Cache → Main Memory → Secondary Storage. Tầng trên nhanh/đắt/dung lượng nhỏ; tầng dưới chậm/rẻ/dung lượng lớn. Mục tiêu: cảm giác bộ nhớ lớn nhưng truy cập nhanh nhờ locality.

Read miss: nạp block chứa địa chỉ từ cấp dưới vào cache, thay victim nếu cần, rồi cung cấp dữ liệu CPU. Hit/Miss ratio tính theo tổng memory requests.

CHAPTER 03 · INTERNAL MEMORY / CHIP ORGANIZATION

Memory cell: hai trạng thái ổn định biểu diễn 0/1; có thể write (ít nhất một lần) và read.

SRAM: flip-flop/logic; giữ dữ liệu khi có nguồn; không refresh; nhanh, đắt, cell lớn; ứng dụng Cache. DRAM: capacitor charge; cần refresh định kỳ; cell nhỏ, rẻ hơn, hỗ trợ Main Memory. Cả hai volatile.

ROM family: ROM non-volatile; PROM program one time; EPROM erase by UV; EEPROM electrically erase/write; Flash là EEPROM được xóa theo block.

Chip organization: W words × n bits/word → total capacity = W×n bits. Ví dụ 1M×16 = 16Mbits = 2MiB (nếu M=2²⁰); address bits = log₂W; data width = n bits.

Không nhầm: số words là số vị trí; bits/word là độ rộng dữ liệu; tổng bits = tích hai đại lượng.

Chip examples: 1M×8 = 8 Mbit = 1 MiB; 1M×16 = 16 Mbit = 2 MiB; 4M×16 = 64 Mbit = 8 MiB (M=2²⁰). Address pins = log₂(number of words); data width = bits/word.

ROM: dữ liệu không mất khi mất điện (non-volatile). PROM chỉ lập trình một lần; EPROM xóa bằng UV; EEPROM xóa/ghi điện; Flash xóa theo block và thường ghi theo page.

CHAPTER 03 · EXTERNAL MEMORY / DISK / RAID / SSD / OPTICAL

Magnetic disk: platter phủ vật liệu từ; head/arm đọc ghi. Track: vòng đồng tâm; Sector: phần track; Cylinder: các track cùng vị trí trên các mặt platter.

Seek time: di chuyển arm/head đến track (startup + traverse + settle). Rotational latency: đợi sector quay dưới head; average = nửa vòng = 30/RPM giây. Transfer time: truyền khối dữ liệu. Access time: gần đúng Seek + Average rotational latency + Transfer (cộng overhead nếu đề cho).

Average rotational latency (s) = 30 / RPM
Total disk access ≈ Seek + Rotational + Transfer (+ controller overhead if given).

RAID: Redundant Array of Independent Disks; kết hợp nhiều disk thành array để cải thiện throughput và/hoặc fault tolerance. RAID 0 striping, không redundancy; RAID 1 mirroring; RAID 5 phân tán parity (cần theo chính xác level trong đề).

SSD/Flash: NAND dùng nhiều trong USB/SSD; không có moving parts; low latency, IOPS cao, nhẹ/ít ồn/ít điện, chống shock tốt hơn HDD; vấn đề: giới hạn số lần ghi, wear leveling, erase-before-write, garbage collection/TRIM và block-level operations.

Optical: CD-ROM chỉ đọc; CD-R ghi một lần; CD-RW ghi/xóa lại; DVD có dung lượng cao hơn CD (theo phân loại slide).

Disk example: 7200 RPM → average rotational latency = 30/7200 s = 0.004167 s ≈ 4.17 ms. Nếu seek=8ms, transfer=1ms, total ≈ 13.17ms (bỏ qua controller overhead).

RAID reminders: RAID 0 = striping/performance, không fault tolerance; RAID 1 = mirroring; RAID 5 = striping + distributed parity, thường chịu lỗi một disk. RAID không thay thế backup.

SSD practical issues: flash pages phải erase theo block trước khi ghi lại; write amplification, limited program/erase cycles, wear leveling và garbage collection ảnh hưởng hiệu năng/tuổi thọ.

CHAPTER 04 · CPU / REGISTERS / FLAGS / ADDRESSING

CPU complexity: multiple cores/roles, protection & privilege, hardware priorities, generality, high speed. Execution mode quyết định instructions hợp lệ, memory region, functional units và privilege; đổi mode tự động bởi hardware hoặc manual bởi program/OS.

User-visible registers: general-purpose, data, addressing (segment/index/stack pointers), condition codes/flags. Control/status: PC/IP, IR, MAR, MBR, status/flags.

x86: AX/BX/CX/DX; SP/BP/SI/DI; CS/DS/SS/ES; IP/FLAGS. 32-bit: EAX…EDI, ESP/EBP, EIP/EFLAGS. x64: RAX…RDI, RSP/RBP, RIP/RFLAGS, R8–R15. CS=code; SS=stack; DS/ES/FS/GS=data segments/selectors.

Flags: CF carry/borrow unsigned; PF parity; AF auxiliary carry; ZF zero; SF sign; OF signed overflow. TF single-step; IF maskable interrupt enable; DF string direction. CF ≠ OF.

Instruction elements: Opcode; operand storage; explicit operands 0/1/2/3; operand location; type/size. Operand types: address, number, character, logical. Address count: 3: C←A OP B; 2: A←A OP B; 1: AC←AC OP A; 0: stack T←(T−1) OP T.

x86 operations: MOV/PUSH/LEA/MOVSX/IN/OUT; ADD/SUB/MUL/DIV/IDIV; NOT/AND/OR/XOR; SHL/SHR/SAR/SAL/ROL/ROR; JMP/CALL/JE/JZ/LOOP; LODS/STOS/MOVS/SCAS.

Real mode 8086/8088: 20-bit physical address 00000h–FFFFFh = 1MiB; logical = Segment:Offset; paragraph boundary divisible by 16; PA=Segment×16+Offset. CS:IP code; DS/ES:BX/SI/DI data; SS:SP stack top; SS:BP stack data/local variables.

Physical address example: Segment=2A30h, Offset=1234h → PA=2A30h×10h+1234h=2B534h. Một physical location có thể viết bằng nhiều cặp Segment:Offset khác nhau.

Addressing modes: Immediate = operand nằm trong instruction (MOV AX,1502h); Direct = address field là EA; Indirect = address field trỏ ô chứa EA; Register = operand ở register; Register-indirect = register giữ địa chỉ (MOV AX,[BX]); Displacement = base/index + displacement; Relative = register + displacement; Indexed = index + displacement; Based-indexed = base+index; Based-indexed+disp = base+index+disp; Stack = implicit top-of-stack.

Segment boundary: paragraph = địa chỉ chia hết cho 16 (10h). Segment 0040h:00AFh, 0030h:01AFh, 0000h:04AFh đều cho cùng physical address 004AFh.

Number of operands: 3-address: C←A OP B; 2-address: A←A OP B; 1-address: AC←AC OP A; 0-address: stack operands ở T và T−1.

CHAPTER 05 · DATA REPRESENTATION / GDB

Positional: N=Σdᵢ×rⁱ. Decimal base10; Binary base2; Octal base8 (digits 0–7); Hex base16 (A–F=10–15). Binary↔Octal nhóm 3 bit; Binary↔Hex nhóm 4 bit. Decimal integer→binary: repeated division; fraction→binary: repeated multiplication by 2.

MSB = bit trái/trọng số cao; LSB = bit phải/trọng số thấp; fractional positions = 2⁻¹, 2⁻², 2⁻³…

Unsigned n-bit: 0…2ⁿ−1. Signed Two’s Complement: −2ⁿ⁻¹…2ⁿ⁻¹−1. Signed magnitude: sign + magnitude, có +0/−0. One’s comp: invert, có hai zero. Two’s comp: invert + 1. Sign extension: lặp sign bit; Zero extension: thêm 0.

Integer sizes: Byte 8; Word 16; Doubleword 32; Quadword 64 bits. Unsigned 8-bit 0–255; signed 8-bit −128–127; unsigned 16-bit 0–65535; signed 16-bit −32768–32767.

CF vs OF: CF dùng carry/borrow khi diễn giải unsigned; OF dùng signed two’s-complement overflow (hai toán hạng cùng dấu, kết quả khác dấu).

String: ASCII từng ký tự; C string có null terminator 00h. “19653” = 5 ký tự + null = 6 bytes; integer 19653 trong Word16 = 2 bytes.

IEEE 754 normalized: Value=(−1)^S×1.F×2^(E−Bias); stored E=e+Bias. Single 32-bit = 1|8|23, Bias 127; Double 64-bit = 1|11|52, Bias 1023. Exponent all 0 → zero/subnormal; all 1 → infinity nếu fraction 0, NaN nếu fraction ≠0.

Endian: Little = LSB byte ở địa chỉ thấp; Big = MSB byte ở địa chỉ thấp. 12345678h: LE 78 56 34 12; BE 12 34 56 78.

Program layout: Text=code; Data=initialized globals/statics; BSS=zero/uninitialized globals/statics; Heap=dynamic allocation; Stack=call frames/local variables.

GDB: break main; run; next; step; continue; print; x/4xb address; info registers; backtrace; quit. x/4xb = examine 4 units, hex, byte-sized.

Two's complement example: −18 (8-bit): +18=00010010; invert=11101101; +1=11101110. Sign-extend to 16-bit = 11111111 11101110. Unsigned 8-bit 0–255; signed 8-bit −128…127.

Binary fraction: 0.625₁₀ = 0.101₂ (0.5+0.125); 13.625₁₀ = 1101.101₂. Binary fraction weights: 1/2, 1/4, 1/8…

IEEE sample teaching format 1|3|4, bias=3: 2.625=10.101₂=1.0101×2¹ → Sign=0, E=1+3=100₂, F=0101 → 01000101₂=45h. −4.75=1|101|0011 → D3h. Đây là format 8-bit mô phỏng, không phải IEEE Single 32-bit.

IEEE special values: exponent=0/fraction=0 → ±0; exponent=0/fraction≠0 → subnormal; exponent all ones/fraction=0 → ±∞; exponent all ones/fraction≠0 → NaN.

Endian example: 32-bit 12345678h at 100h: Little = 78,56,34,12; Big = 12,34,56,78. Endian đổi byte order, không đổi bit order trong một byte.
