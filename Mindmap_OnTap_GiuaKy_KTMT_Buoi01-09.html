01Introduction & Computer OrganizationChapter 00 · Nền tảng kiến trúc máy tính

1. Organization vs Architecture

  • Computer Architecture: thuộc tính nhìn từ phía lập trình viên — tập lệnh (ISA), kiểu dữ liệu/độ rộng bit, cơ chế I/O, phương pháp định địa chỉ.
  • Computer Organization: cách các thành phần vật lý được triển khai và phối hợp — mạch, tín hiệu điều khiển, chân chip, bus, vi kiến trúc.
  • Microarchitecture: cách hiện thực ISA ở mức tổ chức phần cứng bên trong.

2. Structure & Function

  • Structure: cách các thành phần liên kết với nhau.
  • Function: hoạt động/chức năng của từng thành phần trong cấu trúc.

3. Structural components

  • CPU/Processor: điều khiển hệ thống và xử lý dữ liệu.
  • Main Memory: lưu lệnh và dữ liệu đang dùng.
  • I/O: giao tiếp với môi trường bên ngoài.
  • System Interconnection: đường giao tiếp CPU–Memory–I/O.

4. Functional view

  • Data Processing – xử lý dữ liệu; Data Storage – lưu trữ; Data Movement – di chuyển; Control – điều khiển.

5. Computer abstraction / Multi-level machine

Ứng dụng → ngôn ngữ cấp cao → Compiler → Assembly → Assembler → OS/ISA → Microarchitecture → Digital circuits/Physical devices. Mỗi tầng che giấu chi tiết tầng thấp hơn.

6. Von Neumann / IAS – Stored-program concept

  • Lệnh và dữ liệu cùng nằm trong một bộ nhớ đọc/ghi.
  • Bộ nhớ được truy cập theo địa chỉ, không phụ thuộc kiểu dữ liệu.
  • Thực thi tuần tự, trừ khi lệnh điều khiển luồng làm thay đổi thứ tự.
  • IAS: 1.000 từ nhớ × 40 bit; một từ có thể chứa hai lệnh 20 bit; mỗi lệnh = Opcode 8 bit + Address 12 bit.
IAS registers: PC = địa chỉ cặp lệnh tiếp theo; MAR = địa chỉ ô nhớ; MBR = từ dữ liệu/lệnh trao đổi; IR = opcode; IBR = giữ lệnh phải; AC = accumulator; MQ = multiplier-quotient.
02Computer Evolution & Designing for PerformanceChapter 01 · Lịch sử, cân bằng và đánh giá hiệu năng

1. Evolution of computer history

  • Generation 1: Vacuum tubes – kích thước lớn, công suất cao; ví dụ ENIAC.
  • Generation 2: Transistors – nhỏ hơn, tin cậy và hiệu quả hơn.
  • Generation 3: Integrated Circuits (IC).
  • Generation 4: Microprocessors/VLSI – CPU tích hợp trên chip; PC và hệ thống hiện đại.
  • Tiếp theo: đa lõi, MICs/GPGPUs, hệ thống nhúng; theo dõi tiến hóa Intel x86, ARM.

2. Moore’s Law & Memory Wall

  • Moore’s Law: mật độ/transistor trên chip tăng theo xu hướng hàm mũ theo thời gian.
  • Memory Wall: tốc độ CPU tăng nhanh hơn khả năng đáp ứng của bộ nhớ; CPU có thể phải chờ dữ liệu.

3. Microprocessor speed techniques

  • Pipelining: chồng lấp các giai đoạn của nhiều lệnh để tăng thông lượng (throughput); không đồng nghĩa một lệnh đơn luôn ngắn hơn.
  • Branch Prediction: dự đoán nhánh sẽ đi theo hướng nào.
  • Speculative Execution: thực thi trước theo dự đoán; nếu sai thì loại bỏ kết quả sai/khôi phục trạng thái phù hợp.
  • Dataflow analysis: phân tích phụ thuộc dữ liệu; lệnh có toán hạng sẵn sàng có thể được thực thi.

4. Performance balance

  • Cân bằng Processor ↔ Memory ↔ I/O ↔ Interconnect; một thành phần chậm có thể thành bottleneck.
  • Giảm nghẽn CPU–Memory: DRAM rộng hơn/bus dữ liệu rộng hơn; dùng cache nhiều cấp và gần CPU; tăng băng thông interconnect.

5. Performance assessment

  • Active/Dynamic power: công suất khi mạch chuyển trạng thái/hoạt động.
  • Static power: công suất rò/leakage khi mạch vẫn được cấp nguồn.
  • Benchmark suite: tập chương trình chuẩn để so sánh hệ thống.
  • Clock rate và CPI phải xem cùng Instruction Count; tăng GHz không tự động bảo đảm chương trình chạy nhanh hơn.
Iron Law: CPU time = Instruction Count × Average CPI × Clock Cycle Time = IC × CPI / Clock Rate.
MIPS: Million Instructions Per Second = IC / (Execution time × 10⁶) = Clock rate / (CPI × 10⁶), khi đơn vị phù hợp. MIPS không luôn là cách so sánh công bằng giữa ISA/chương trình khác nhau.
Amdahl: Speedup = 1 / [(1 − P) + P/S], với P là phần được cải tiến, S là speedup của phần đó. Giới hạn khi S→∞: 1/(1−P).
03Instruction Cycle & InterruptsChapter 02 · Chu kỳ lệnh, Polling và ngắt

1. Computer function

Thực thi chương trình là lặp lại quá trình lấy lệnh và thực thi lệnh; lệnh được nạp vào Instruction Register (IR).

2. Instruction Cycle

  • Fetch: lấy lệnh từ bộ nhớ vào IR; PC chỉ vị trí lệnh tiếp theo.
  • Decode: giải mã Opcode để biết thao tác.
  • Indirect cycle: chỉ khi cần lấy địa chỉ toán hạng gián tiếp.
  • Execute: thực thi thao tác, có thể lấy toán hạng, tính toán, ghi kết quả hoặc đổi PC.
  • Interrupt check/cycle: kiểm tra và xử lý ngắt nếu đang chờ và được cho phép; sau đó quay lại lệnh tiếp theo.

State labels: IAC (Instruction Address Calculation), IF (Instruction Fetch), IOD (Instruction Operation Decode), OAC (Operand Address Calculation), OF (Operand Fetch), DO (Data Operation), OS (Operand Store), IC (Interrupt Check).

3. Polling vs Interrupt

4. Interrupt handling

IRQ → CPU nhận biết (thường sau khi hoàn tất lệnh hiện tại) → Save context (PC/flags và thanh ghi cần thiết) → lấy địa chỉ ISR từ vector → chạy ISR → restore context → return (IRET/RETI tùy kiến trúc).

Interrupt types trong slide: Program/software exception (overflow, divide by zero, illegal instruction); Timer (hardware); I/O (hardware); Hardware failure (hardware).

5. Multiple interrupts

  • Sequential: xử lý ISR lần lượt; ISR hiện tại xong rồi mới nhận ISR tiếp theo theo chính sách.
  • Nested: ISR ưu tiên cao có thể chen vào ISR ưu tiên thấp; phải lưu/khôi phục nhiều lớp trạng thái.
Nhớ: Interrupt không làm mất chương trình chính; CPU lưu trạng thái để quay lại. Polling = CPU hỏi; Interrupt = thiết bị báo.
04Computer Interconnection & Bus ArchitectureChapter 02 · Các module, Bus và liên kết điểm-điểm

1. Interconnection structures

Computer là mạng các module cơ bản; tập hợp đường kết nối giữa module gọi là Interconnection Structure.

  • Memory module: N từ có cùng độ dài; địa chỉ duy nhất 0…N−1; đọc/ghi từ dữ liệu.
  • I/O module: giao tiếp thiết bị; có thể gửi tín hiệu ngắt đến processor.
  • Processor: đọc lệnh/dữ liệu, xử lý, ghi dữ liệu và phát tín hiệu điều khiển; nhận interrupt.

2. Bus structure & bus types

  • Data Bus: truyền dữ liệu.
  • Address Bus: xác định địa chỉ nguồn/đích; độ rộng liên quan không gian địa chỉ.
  • Control Bus: tín hiệu điều khiển/trạng thái như Read, Write, Interrupt, Clock.
  • Bus hierarchy: nhiều cấp bus giúp đáp ứng chênh lệch tốc độ và loại thiết bị.
  • Bus arbitration: quyết định thiết bị nào được quyền dùng bus khi tranh chấp.
  • Synchronous timing: đồng bộ theo clock; Asynchronous timing: phối hợp bằng handshaking/tín hiệu bắt tay.

3. Bus vs Point-to-Point

  • Shared bus: nhiều thiết bị dùng chung đường truyền; đơn giản nhưng có tranh chấp/bottleneck.
  • Point-to-point: liên kết riêng giữa hai đầu; tăng băng thông và giảm chia sẻ đường truyền.

4. Intel QPI & PCI Express

  • QPI (QuickPath Interconnect): liên kết point-to-point tốc độ cao; có truyền hai chiều; slide minh họa 3.2 GHz, 2 lần truyền/chu kỳ → 6.4 GT/s và 12.8 GB/s mỗi hướng (mức lý thuyết của ví dụ).
  • PCIe: liên kết nối tiếp point-to-point; dùng Lane (các cặp đường truyền); có thể ghép x1, x4, x8, x16 để tăng băng thông. Phân biệt tốc độ mỗi lane và tổng lane.
Điểm thi: nhận diện Data/Address/Control bus; phân biệt synchronous/asynchronous; shared bus/point-to-point; nắm QPI transfer rate theo ví dụ slide.
05Memory Hierarchy & Cache PrinciplesChapter 03 · Tổng quan bộ nhớ, tính cục bộ và Cache

1. Memory characteristics / design constraints

  • Đặc tính thường xét: vị trí (location), dung lượng (capacity), đơn vị truyền, phương pháp truy cập, hiệu năng (access time/cycle time/transfer rate), công nghệ và tính chất vật lý.
  • Ba ràng buộc: How much? (capacity), How fast? (access time), How expensive? (cost).
  • Fast access → cost/bit cao; capacity lớn → cost/bit thấp và thường access time chậm hơn.

2. Memory hierarchy

Registers → Cache (L1/L2/L3) → Main Memory (DRAM) → Secondary storage (SSD/HDD) → Optical/removable/archive.

  • Đi xuống hierarchy: cost/bit giảm; capacity tăng; access time tăng; tần suất CPU truy cập trực tiếp giảm.

3. Locality of reference

  • Temporal: dữ liệu/lệnh vừa dùng có khả năng được dùng lại sớm.
  • Spatial: địa chỉ gần nhau có xu hướng được truy cập.
  • Sequential: lệnh thường được lấy theo thứ tự liên tiếp.

4. Cache basics

  • Cache nhỏ và nhanh hơn Main Memory; lưu bản sao các block được dùng gần đây/được dự đoán sẽ dùng.
  • Hit: yêu cầu được phục vụ từ Cache. Miss: không có block, cần lấy từ cấp dưới và nạp vào Cache.
  • L1 gần CPU, rất nhanh/nhỏ; L2 lớn hơn; có thể có L3.
Hit ratio = số Cache hits / tổng số yêu cầu. Miss ratio = số Cache misses / tổng số yêu cầu = 1 − Hit ratio.

1. Ba Cache mapping schemes

2. Address fields

  • Offset/Word: chọn byte/word trong block; nếu block có B byte → offset bits = log₂B.
  • Index/Line: chọn line (direct) hoặc set (set-associative).
  • Tag: xác nhận block nào đang nằm tại line/set.
  • Với địa chỉ byte: offset bits = log₂(block size); index bits = log₂(lines hoặc sets); tag = address bits − index − offset.

3. Replacement policy

Khi set/Cache không còn chỗ, chọn block victim để thay. Các ví dụ thường gặp: LRU (ít dùng gần đây nhất), FIFO (vào trước ra trước), Random. Áp dụng theo quy tắc cụ thể mà đề cho.

4. Cache write policy

  • Write-through: ghi đồng thời Cache và Main Memory; đơn giản, nhất quán hơn nhưng tăng traffic ghi.
  • Write-back: chỉ ghi xuống Main Memory khi block bị đẩy ra; giảm traffic, cần theo dõi dirty/modified bit.
Thứ tự giải bài mapping: xác định block size → số lines/sets → tách Offset, Index/Set, Tag → tìm line/set → so Tag để kết luận Hit/Miss → nếu Miss thì chọn victim theo policy.
07Internal Memory & External MemoryChapter 03 · Bán dẫn, đĩa từ, RAID, SSD và Optical

1. Semiconductor memory

  • Memory cell có hai trạng thái ổn định biểu diễn 0/1; hỗ trợ ghi và đọc.
  • SRAM: lưu bằng flip-flop/logic; không cần refresh khi có nguồn; nhanh, đắt, cell lớn; thường dùng Cache.
  • DRAM: lưu điện tích tụ điện; cần refresh định kỳ; cell nhỏ, rẻ/dung lượng cao hơn; thường dùng Main Memory.
  • Cả SRAM và DRAM đều volatile – mất dữ liệu khi mất điện.

2. ROM family

  • ROM: non-volatile; dữ liệu cố định.
  • PROM: lập trình được một lần.
  • EPROM: xóa bằng tia UV rồi ghi lại.
  • EEPROM: xóa/ghi bằng điện, có thể cập nhật từng nội dung.
  • Flash: một dạng EEPROM, xóa theo khối và nhanh hơn trong cách dùng lưu trữ.

3. Magnetic disk (HDD)

Đĩa platter phủ vật liệu từ; đầu đọc/ghi (head); dữ liệu trên mặt đĩa được tổ chức thành tracks, chia sectors; các track cùng vị trí trên nhiều mặt đĩa tạo thành cylinder.

  • Seek time: thời gian di chuyển đầu đọc đến track.
  • Rotational latency: chờ sector quay đến đầu đọc (trung bình nửa vòng).
  • Transfer time: thời gian truyền dữ liệu.
  • Access time: tổng thời gian định vị + chờ quay + truyền (có thể cộng controller overhead nếu bài cho).

4. RAID / SSD / Optical

  • RAID: ghép nhiều disk thành array để tăng performance và/hoặc reliability/redundancy; phân biệt mục tiêu từng level theo slide.
  • SSD: Flash memory, không có bộ phận chuyển động; access latency thấp, IOPS cao, chống sốc tốt, ít ồn/ít điện hơn HDD; lưu ý write endurance, wear leveling, garbage collection/TRIM.
  • Optical: CD-ROM (đọc), CD-R (ghi một lần), CD-RW (ghi/xóa lại), DVD.
Chip capacity: W × n bits (W words, mỗi word n bits). Ví dụ 1M × 8 = 8 Mbits = 1 MiB (nếu dùng M theo 2²⁰ trong bài tổ chức chip).
08CPU Architecture, Registers & AddressingChapter 04 · CPU, thanh ghi, lệnh máy và phân đoạn

1. CPU complexity / execution modes

  • Nguyên nhân phức tạp: multiple cores, multiple roles, protection/privilege, hardware priorities, generality, high speed.
  • Execution mode quyết định lệnh nào hợp lệ, vùng nhớ được truy cập, functional units và privilege.
  • Mode change có thể tự động do hardware hoặc chủ động bởi chương trình/hệ điều hành.
  • Privilege & Protection: OS cần quyền cao; ứng dụng chạy với quyền hạn chế.

2. Register organization

  • User-visible: General-purpose, Data, Address (segment pointers/index/stack pointers), Condition codes/flags.
  • Control & Status: PC/IP, IR, MAR, MBR, flags/status register.
  • x86 16-bit: AX, BX, CX, DX; SP, BP, SI, DI; CS, DS, SS, ES; IP; FLAGS.
  • x86 32-bit: EAX, EBX, ECX, EDX, ESP, EBP, ESI, EDI; EIP/EFLAGS; segment registers.
  • x64: RAX, RBX, RCX, RDX, RSP, RBP, RSI, RDI, RIP, RFLAGS; mở rộng general-purpose registers (R8–R15).

3. Important flags

  • CF: Carry – carry/borrow trong phép toán không dấu.
  • PF: Parity; AF: Auxiliary carry; ZF: Zero; SF: Sign; OF: Signed overflow.
  • TF: Trap/single-step; IF: Interrupt enable; DF: Direction for string operations.

4. Machine instruction

Thành phần: Opcode/operation; vị trí lưu operand; số operand tường minh (0/1/2/3); vị trí operand; kiểu và kích thước operand. Operand: address, number, character, logical data.

Logical / Shift / RotateAND, OR, XOR, NOT, SHL, SHR, SAR, ROL, ROR

5. x86 Real Mode segmentation (8086/8088)

  • 20-bit physical address space: 00000h–FFFFFh = 1 MiB; registers segment/offset 16-bit.
  • Logical address: Segment:Offset.
  • Physical Address: PA = Segment × 16 + Offset = (Segment << 4) + Offset.
  • Segment starts at paragraph boundary (địa chỉ chia hết cho 16); segment length tối đa 64 KiB; nhiều cặp Segment:Offset có thể trỏ cùng Physical Address.
  • CS:IP code/next instruction; DS/ES:BX/SI/DI data; SS:SP top of stack; SS:BP stack data/local variables.

6. Addressing modes

Immediate (giá trị nằm trong lệnh); Direct (trường địa chỉ là EA); Indirect (địa chỉ trỏ đến ô nhớ chứa EA); Register; Register Indirect; Displacement/Relative/Indexed; Based-Indexed; Based-Indexed + Displacement; Stack.

Real-mode example: 2A30h:1234h → PA = 2A30h×10h + 1234h = 2B534h. Đừng nhầm Logical address với Physical address.
09Number Systems & Data RepresentationChapter 05 · Số nguyên, chuỗi, số thực, Endian và GDB

1. Number systems & binary fraction

  • Positional system: giá trị = tổng digit × radix^vị trí. Decimal base 10; Binary base 2; Octal base 8; Hexadecimal base 16 (A–F = 10–15).
  • Binary ↔ Octal: nhóm 3 bit; Binary ↔ Hex: nhóm 4 bit; số nguyên decimal → Binary bằng chia liên tiếp 2; phần thập phân → Binary bằng nhân liên tiếp 2.
  • MSB: bit trọng số lớn nhất (trái); LSB: bit trọng số nhỏ nhất (phải).
  • Phần lẻ: vị trí sau dấu chấm có trọng số 2⁻¹, 2⁻², 2⁻³…

2. Signed integers

  • Unsigned n-bit: 0…2ⁿ−1.
  • Signed magnitude: 1 sign + magnitude; có +0 và −0.
  • One’s complement: số âm = đảo bit số dương; có hai số 0.
  • Two’s complement: đảo bit + 1; n-bit range = −2ⁿ⁻¹…2ⁿ⁻¹−1.
  • Sign extension: lặp sign bit khi tăng độ rộng signed; Zero extension: thêm 0 bên trái cho unsigned.
  • Byte 8, Word 16, Doubleword 32, Quadword 64 bits.

3. Addition / strings

  • Unsigned overflow → xét CF; signed two’s complement overflow → xét OF. Hai cờ không đồng nghĩa.
  • String: ký tự thường lưu theo ASCII; chuỗi C kết thúc bằng Null (0x00). "19653" = 5 ký tự + null = 6 byte; số 19653 lưu Word = 2 byte.

4. Floating-point / IEEE 754

  • Chuẩn hóa dạng (−1)^S × 1.F × 2^e; exponent lưu = e + Bias; mantissa/fraction bỏ hidden leading 1 với normal numbers.
  • Single 32-bit: 1 Sign + 8 Exponent + 23 Fraction; Bias = 127.
  • Double 64-bit: 1 Sign + 11 Exponent + 52 Fraction; Bias = 1023.
  • Exponent toàn 0: zero/subnormal; exponent toàn 1: infinity/NaN (tùy fraction).

5. Endian / memory layout / GDB

  • Little-endian: LSB byte ở địa chỉ thấp nhất. Big-endian: MSB byte ở địa chỉ thấp nhất.
  • Text: machine code; Data: dữ liệu global/static đã khởi tạo; BSS: global/static zero hoặc chưa khởi tạo tường minh; Heap: cấp phát động; Stack: call frame/local variables.
  • GDB: break đặt breakpoint; run chạy; next chạy dòng kế; step đi vào hàm; continue tiếp tục; print xem giá trị; x/4xb xem 4 byte hex.
Điểm cần nhớ theo slide: Octal là Base 8 (slide ghi Base 7 nhưng chính nó liệt kê chữ số 0–7); ví dụ e7 có nhãn độ rộng trường không khớp phép tính, không dùng nhãn sai làm quy tắc.

Công thức cần thuộc / biết áp dụng

Ưu tiên các phép tính có thể xuất hiện trong bài giữa kỳ

1 · CPU Execution Time (Iron Law)

CPU time = IC × CPI × TcycleCPU time = (IC × CPI) / Clock rate

IC = instruction count; CPI = cycles/instruction; Tcycle = 1/frequency.

2 · Average CPI

CPIavg = Σ(ICᵢ × CPIᵢ) / ΣICᵢ

Nếu đề cho tỷ lệ instruction: CPIavg = Σ(fractionᵢ × CPIᵢ).

3 · MIPS

MIPS = IC / (Execution time × 10⁶)MIPS = Clock rate / (CPI × 10⁶)

Đơn vị: triệu lệnh mỗi giây; lưu ý khi so sánh CPU/ISA khác nhau.

4 · Amdahl’s Law

Speedup = 1 / [(1−P) + P/S]Smax = 1 / (1−P)

P = phần chương trình được cải tiến; S = speedup phần đó.

5 · Cache ratios

Hit ratio = Hits / Total requestsMiss ratio = Misses / Total = 1 − Hit ratio

Chú ý phân biệt Cache hit/miss với page hit/miss trong ngữ cảnh khác.

6 · Cache mapping

Direct line = Block no. mod LinesSet = Block no. mod Sets

Offset bits = log₂(block bytes); index bits = log₂(lines/sets); tag = address bits − index − offset.

7 · Disk performance

Access time ≈ Seek + Avg rotational latency + TransferAvg latency = ½ rotation = 30/RPM seconds

Nếu đề cho controller overhead, cộng thêm vào tổng thời gian.

8 · Real Mode address

PA = Segment × 16 + Offset

Ví dụ 2A30h:1234h → 2A300h + 1234h = 2B534h. Địa chỉ vật lý 20-bit trong 8086/8088.

9 · Positional number

N = Σ dᵢ × rⁱ

Binary fraction: bên phải dấu chấm lần lượt ×2⁻¹, ×2⁻², ×2⁻³…

10 · Integer ranges

Unsigned n-bit: 0 … 2ⁿ−1Signed 2’s comp: −2ⁿ⁻¹ … 2ⁿ⁻¹−1

8-bit unsigned: 0–255; signed: −128–127. 16-bit signed: −32768–32767.

11 · IEEE 754

Value = (−1)^S × 1.F × 2^(E−Bias)

Single: Bias 127; Double: Bias 1023. Stored exponent E = e + Bias.

12 · QPI example (slide)

3.2 GHz × 2 transfers/clock = 6.4 GT/s6.4 GT/s × 16 bits ÷ 8 = 12.8 GB/s / direction

Đây là số liệu ví dụ QPI trong slide, không tổng quát cho mọi link.

Những chỗ dễ mất điểm

Đọc nhanh trước khi vào phòng kiểm tra

1. Đừng đồng nhất CPI thấp với CPU luôn nhanh hơn.
Execution time phụ thuộc đồng thời Instruction Count, Average CPI và Clock Cycle Time.
2. Pipelining không làm mọi lệnh đơn lẻ chạy nhanh hơn tương ứng số stage.
Nó chủ yếu tăng throughput nhờ chồng lấp các giai đoạn; hazard/stall/branch penalty vẫn ảnh hưởng.
3. Polling khác Interrupt.
Polling: CPU liên tục kiểm tra; Interrupt: phần cứng gửi yêu cầu, CPU xử lý theo cơ chế interrupt handling.
4. Direct mapping, Associative và Set-associative.
Direct: chỉ một line; fully associative: bất cứ line; set-associative: một set cụ thể, nhiều line có thể chọn.
5. SRAM/DRAM và ROM family.
SRAM không refresh; DRAM cần refresh. PROM một lần; EPROM tia UV; EEPROM/Flash xóa bằng điện (Flash theo block).
6. Seek, rotational latency, transfer time.
Seek = di chuyển head; rotational = chờ sector; transfer = truyền dữ liệu; access time thường gồm ba thành phần trên.
7. Real-mode address.
PA = Segment × 16 + Offset. Không cộng Segment và Offset trực tiếp; phải dịch Segment sang trái 4 bit.
8. Signed/Unsigned và CF/OF.
Bit pattern giống nhau nhưng diễn giải khác nhau. CF là carry-out cho unsigned; OF là tràn signed.
9. IEEE 754.
Single: 1|8|23, Bias 127. Double: 1|11|52, Bias 1023. Mantissa fraction của normalized number không lưu leading 1.
10. Data vs BSS và String.
Global initialized → Data; global zero/uninitialized → BSS; string có thêm Null terminator (nếu C string).
11. Sửa lỗi đã phát hiện trong slide Chapter 05.
Octal phải là Base 8 vì chữ số dùng là 0–7. Slide 37 ví dụ e7 có nhãn độ dài trường sai; phải căn cứ phép tính/cấu trúc thực tế đã học, không học thuộc nhãn lỗi. Giá trị 65530₁₀ = FFFAh, không phải FFF0h.

B1 · NHẬP MÔN / IAS (CHAPTER 00)

Architecture: thuộc tính nhìn từ programmer: ISA, kiểu/độ rộng dữ liệu, I/O, addressing.

Organization: triển khai phần cứng: mạch, tín hiệu, control, bus; microarchitecture hiện thực ISA.

Structure = cách thành phần liên kết; Function = hoạt động của từng thành phần.

4 functions: Data Processing · Data Storage · Data Movement · Control.

Components: CPU · Main Memory · I/O · System Interconnection.

Abstraction: Application → HLL → Compiler → Assembly → Assembler → OS/ISA → Microarchitecture → Digital circuits.

Von Neumann: lệnh + dữ liệu chung một read/write memory; bộ nhớ addressable; execution tuần tự trừ khi đổi luồng.

IAS: 1000 words × 40 bits; 1 word = 2 instructions × 20 bits; mỗi instruction = Opcode 8 + Address 12.

IAS registers: PC (next instruction pair), MAR (memory address), MBR (word read/write), IR (opcode), IBR (right-hand instruction), AC (accumulator), MQ (multiplier-quotient).

B2 · EVOLUTION & PERFORMANCE (CHAPTER 01)

Generations: Vacuum tube → Transistor → IC → Microprocessor/VLSI → multicore/GPU era. ENIAC = first general-purpose electronic digital computer (slide); IAS = stored-program prototype.

Moore’s Law: transistor density tăng theo xu hướng hàm mũ. Memory Wall: CPU nhanh hơn độ đáp ứng/băng thông memory → chờ dữ liệu.

Speed techniques: Pipelining = overlap stages; Branch Prediction = dự đoán nhánh; Speculative Execution = chạy trước theo dự đoán; Dataflow analysis = phụ thuộc/toán hạng sẵn sàng.

Performance balance: cân bằng CPU–Memory–I/O–Interconnect; tăng bus width, cache nhiều cấp/gần CPU, tăng interconnect bandwidth.

Power: Active/Dynamic = switching; Static = leakage khi vẫn cấp nguồn. Benchmark suite dùng so sánh workload chuẩn.

IRON LAW · CPI · MIPS · AMDAHL

CPU time = IC × CPI × Tcycle = IC × CPI / Clock rate
Average CPI = Σ(ICᵢ×CPIᵢ) / ΣICᵢ = Σ(fractionᵢ×CPIᵢ)
MIPS = IC/(Execution time×10⁶) = Clock rate/(CPI×10⁶)
Amdahl speedup = 1/[(1−P)+P/S]; max = 1/(1−P)

P = fraction improved; S = speedup of improved part. Giảm CPI hay tăng clock không tự đảm bảo nhanh hơn nếu IC/timing đổi.

B3 · INSTRUCTION CYCLE / INTERRUPT (CHAPTER 02)

Cycle: Fetch → Decode → Indirect (nếu cần) → Execute → Interrupt check (nếu có) → Fetch next.

Polling: CPU chủ động kiểm tra status/command-ready bit. Interrupt: thiết bị/controller gửi IRQ để yêu cầu CPU.

Handling: IRQ → finish current instruction → save context (PC/flags/registers cần thiết) → vector/ISR address → execute ISR → restore context → IRET/return.

Types: Program/software exception (overflow, divide by zero, illegal instruction); Timer, I/O, Hardware failure.

Sequential: xử lý ISR lần lượt. Nested: ngắt ưu tiên cao chen vào ISR thấp.

B4 · INTERCONNECTION / BUS (CHAPTER 02)

Memory module: N words, địa chỉ 0…N−1, read/write. I/O module: giao tiếp ngoài, có thể phát interrupt. Processor: đọc lệnh/dữ liệu, xử lý, ghi kết quả, phát control.

Data bus: dữ liệu. Address bus: địa chỉ nguồn/đích. Control bus: Read/Write/Interrupt/Clock/status.

Bus hierarchy: nhiều bus/cấp để cân bằng tốc độ. Arbitration: chọn bus master khi tranh chấp.

Synchronous: theo clock. Asynchronous: handshaking. Shared bus: chung đường, dễ nghẽn. Point-to-point: kết nối riêng.

QPI example slide: 3.2 GHz × 2 = 6.4 GT/s; 16 bit/transfer → 12.8 GB/s mỗi hướng (số ví dụ lý thuyết trên slide). PCIe: serial point-to-point; Lane x1/x4/x8/x16.

B5 · MEMORY HIERARCHY / CACHE (CHAPTER 03)

Constraints: Capacity – Access time – Cost. Fast access → cost/bit cao; capacity lớn → cost/bit thấp và access time thường tăng.

Hierarchy: Registers → L1 → L2 → L3 → DRAM/Main memory → SSD/HDD → Optical/archive.

Đi xuống hierarchy: cost/bit ↓; capacity ↑; access time ↑; processor access frequency ↓.

Locality: Temporal = dùng lại gần đây; Spatial = địa chỉ gần nhau; Sequential = lệnh liên tiếp.

Cache: nhỏ/nhanh hơn main memory. Hit = có block; Miss = không có, lấy từ cấp dưới. L1 nhỏ/nhanh, L2 lớn hơn, có thể L3.

Hit ratio = Hits / Total requests
Miss ratio = Misses / Total = 1 − Hit ratio

B6 · CACHE MAPPING & POLICY

MappingQuy tắc
DirectBlock chỉ đến 1 line; line = block no. mod lines.
Fully associativeBlock ở bất kỳ line nào.
Set-associativeBlock đến 1 set; set = block no. mod sets; chọn line trong set.

Address: Offset chọn byte/word trong block; Index chọn line/set; Tag nhận diện block. Offset bits=log₂(block bytes); Index bits=log₂(lines/sets); Tag bits=Address bits−Index−Offset.

Replacement: chọn victim khi hết chỗ (ví dụ LRU/FIFO/Random theo đề). Write-through: ghi Cache + Memory ngay. Write-back: ghi Memory khi block bị thay; theo dõi dirty bit.

B7 · INTERNAL / EXTERNAL MEMORY

SRAM: flip-flop; không refresh; nhanh/đắt/cell lớn; Cache. DRAM: capacitor; refresh; chậm hơn/rẻ/cell nhỏ; Main memory. Cả hai volatile.

ROM: non-volatile; PROM: program once; EPROM: UV erase; EEPROM: electrically erase/write; Flash: erase by block.

HDD: platter/head; tracks, sectors, cylinders. Seek: di chuyển head; Rotational latency: chờ sector; Transfer: truyền dữ liệu.

Access time ≈ Seek + Average rotational latency + Transfer
Average rotational latency = 30/RPM seconds

RAID: nhiều disk thành array nhằm performance/redundancy theo level. SSD: flash, không moving parts, low latency/IOPS cao; chú ý endurance/wear leveling. Optical: CD-ROM đọc; CD-R ghi một lần; CD-RW ghi/xóa lại; DVD.

B8 · CPU / REGISTER ORGANIZATION (CHAPTER 04)

Execution mode quyết định instruction hợp lệ, memory region, functional units và privilege. Protection: OS quyền cao; application quyền hạn chế. Mode change: automatic (hardware) / manual (program/OS).

User-visible registers: General-purpose, Data, Address (segment/index/stack), Flags/condition codes. Control & status: PC/IP, IR, MAR, MBR, flags/status.

Instruction elements: Opcode; operand storage/location; explicit operands (0/1/2/3); operand size/type. Operand types: address, number, character, logical.

X86 REAL MODE / SEGMENTATION (8086/8088)

20 address lines → physical space 00000h–FFFFFh = 1 MiB. 16-bit Segment + 16-bit Offset.

PA = Segment × 16 + Offset = (Segment << 4) + Offset

Segment boundary: paragraph boundary chia hết cho 16; segment tối đa 64 KiB. Một Physical Address có thể viết bằng nhiều cặp Segment:Offset.

Registers: CS:IP = next instruction; DS/ES:BX/SI/DI = data; SS:SP = top of stack; SS:BP = stack data/local variable.

Addressing modes: Immediate = value in instruction; Direct = address field is EA; Indirect = field trỏ đến nơi chứa EA; Register; Register Indirect; Displacement/Relative/Indexed; Based-Indexed; Based-Indexed + displacement; Stack.

BINARY / BASE CONVERSION (CHAPTER 05)

Positional: N = Σ dᵢ × baseⁱ. Decimal 10; Binary 2; Octal 8 (digits 0–7); Hex 16 (0–9,A–F).

Binary → Octal: nhóm 3 bit. Binary → Hex: nhóm 4 bit. Decimal integer → chia liên tiếp base; decimal fraction → nhân liên tiếp base.

MSB: most significant bit (trái). LSB: least significant bit (phải). Fraction bits: 2⁻¹, 2⁻², 2⁻³…

SIGNED INTEGER / RANGE EXTENSION

Unsigned n-bit: 0 … 2ⁿ−1
Signed 2’s comp: −2ⁿ⁻¹ … 2ⁿ⁻¹−1

8-bit unsigned 0…255; signed −128…127. 16-bit unsigned 0…65535; signed −32768…32767.

Sign-magnitude: sign + magnitude; có +0 và −0. One’s comp: đảo bit; có hai zero. Two’s comp: đảo bit +1.

Negate: invert all bits → add 1. Sign extension: copy sign bit to left; Zero extension: fill zeros on left (unsigned).

CF: carry-out/borrow cho unsigned. OF: signed overflow. Hai cờ độc lập. Signed addition overflow khi hai toán hạng cùng dấu nhưng kết quả khác dấu.

INTEGER / STRING / FLOATING-POINT

Integer sizes: Byte 8; Word 16; Doubleword 32; Quadword 64 bits.

String: ASCII code từng ký tự; null-terminated string có thêm 00h. "19653" = 5 chars + null = 6 bytes; integer 19653 trong 16-bit Word = 2 bytes.

IEEE 754: Value = (−1)^S × 1.F × 2^(E−Bias) (normalized). E = e + Bias; hidden leading 1 không lưu trong fraction.

FormatSignExponentFractionBias
Single 321823127
Double 64111521023

Exponent all 0 → zero/subnormal; all 1 → Infinity (fraction=0) / NaN (fraction≠0).

ENDIAN / MEMORY LAYOUT / GDB

Little-endian: least significant byte at lowest address. Big-endian: most significant byte at lowest address.

Ví dụ 0x12345678 tại 100h: Little = 78 56 34 12; Big = 12 34 56 78.

Text: code; Data: initialized global/static; BSS: zero/uninitialized global/static; Heap: dynamic allocation; Stack: function frames/local variables.

GDB: break main (breakpoint); run; next (next source line); step (step into); continue; print var; x/4xb addr (4 bytes, hex); info registers; backtrace; quit.

5 CẶP DỄ NHẦM NHẤT

1. CF ≠ OF: CF unsigned carry; OF signed overflow.

2. Data ≠ BSS: initialized nonzero vs zero/uninitialized globals.

3. Little ≠ Big: LSB byte first vs MSB byte first.

4. Direct ≠ Indirect: field gives effective address vs field points to memory containing effective address.

5. Segment ≠ Offset: PA = Segment×16 + Offset; không cộng trực tiếp.
